# 旁白生成路由

完整讲解片需要旁白时读取本文件。单条 B-roll 不执行本路由；其模型原始音轨按原样保留。

## 目录

1. 通用输出要求
2. 一级：Agent 自带或内置 TTS
3. 二级：即梦 CLI
4. 三级：其他语音平台或用户回传
5. 全部不可用时

## 1. 通用输出要求

- 每个 beat 单独生成，保存为 `<project>/assembly/vo/<序号>.wav`。
- 优先输出 24 kHz、单声道 PCM WAV；其他格式先保留原件，再用 ffmpeg 转为该规格。
- 文本必须逐字对应 `beats.json` 的 `line`，不擅自增删内容。
- 延续同一音色、语速、情绪和响度；默认平静、克制、干净利落。
- 生成后用 ffprobe 检查音频可读、时长大于零，再交给 `assemble.py`。
- 在 beat 中记录 `voice_generation_route`、`voice_generation_platform`、`voice_generation_model`。
- 任何付费或扣积分调用，首次提交前说明预计消耗并征得用户确认。

## 2. 一级：Agent 自带或内置 TTS

先检查当前 Agent 的工具声明，确认它能从文本生成可保存的语音音频。可用时直接使用，不再检测即梦或询问其他平台。

执行要求：

1. 确认支持中文、指定音色或风格，并能返回音频文件。
2. 逐 beat 生成，保持同一 speaker/voice 设置。
3. 将实际工具、模型和音色写入 manifest。
4. 若工具只有实时播放、不能保存文件，则不视为可用，进入下一级。

## 3. 二级：即梦 CLI

Agent 没有语音能力时，检测即梦官方 CLI。可执行文件通常为 `dreamina`；Windows 安装也可能位于 `~/bin/dreamina.exe`。

必须先运行：

```bash
dreamina --help
```

只在当前帮助真实列出 TTS、text-to-speech、speech、voice、narration、语音或配音生成命令时使用。随后运行该子命令的 `--help`，以实时参数为准，不在 Skill 中猜测命令名或参数。

若 CLI 提供语音命令：

1. 检查登录状态和积分余额。
2. 确认中文、音色、输出格式和异步任务回收方式。
3. 首次扣积分前征得用户确认。
4. 先试生成一个 beat，验证后再批量。

若 CLI 只列出图片/视频命令，或 `tts` 等命令返回 unknown command：记录“当前即梦 CLI 不支持独立旁白生成”，进入其他语音平台路线。不要从带原声视频中抽取并冒充可控旁白。

截至本 Skill 最近一次本机实测，即梦 CLI build `b5ccc5d`（2026-07-21）没有列出语音/TTS 命令；这是版本实测，不代表后续版本永远不支持，因此每次仍以 `dreamina --help` 为准。

## 4. 三级：其他语音平台或用户回传

前两级不可用时，先询问用户是否有常用语音生成平台或官方 CLI。

若用户有平台：

1. 要求用户提供官方 CLI 安装命令或官方文档链接。
2. 读取实时帮助，确认中文 TTS、音色、格式、费用和任务回收方式。
3. 只使用官方授权流程，不索取 Cookie、浏览器 token 或账号密码。
4. 首次扣费前征得用户确认，先试生成一个 beat。

若用户没有平台：

1. 整理逐 beat 文本清单，包含序号、原文、角色和目标文件名。
2. 额外提供统一音色要求：中文、平静克制、语速一致、干净利落、不要背景音乐。
3. 推荐用户自行选择当前可用的语音平台生成，并回传逐 beat 音频或一条完整旁白。
4. 用户回传后统一转为 24 kHz 单声道 WAV，执行 ffprobe QA，并记录实际平台和模型。

不要替用户虚构平台、模型、CLI 或费用。平台不明确时，保持供应商中立。

## 5. 全部不可用时

停止旁白生成，列出缺失项，并请用户上传逐 beat 音频或一条完整旁白。不要创建空 WAV，也不要在缺少 `vo` 文件时宣称完整讲解片可以拼装。
